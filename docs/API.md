# PiCache REST API (v1)

Base path `/api/v1`. JSON only (`Content-Type: application/json` for request bodies; unknown members are rejected). Timestamps in entities are RFC 3339 (UTC); time series use unix seconds. Types in `code` refer to Go types (`package.Type`) whose JSON field names are authoritative.

**Auth.** Browser: session cookie set by login/setup (`HttpOnly`, `SameSite=Strict`, `Path=/`): `__Host-picache_session` (always `Secure`) when the request's effective scheme is https (it arrived over TLS, or a peer in `web.trustedProxies` sent `X-Forwarded-Proto: https`), `picache_session` otherwise (`Secure` only with `PICACHE_WEB_SECURE_COOKIES=true`, for a TLS-terminating reverse proxy that is not trusted). Both names are accepted. Login and setup also set a device cookie, named the same way (`__Host-picache_device` over https, `picache_device` otherwise; `HttpOnly`, `SameSite=Strict`, 180 days, sealed with the master key, renewed at every sign-in, kept on logout). It is not a credential: a later sign-in with the same username from that browser is throttled by the device (5 failures → 15 min) instead of the username delay. Automation: `Authorization: Bearer <token>` (API tokens, scope `read`, `admin` or, since v0.15.0, `sync`). Permissions:
- **P** public
- **R** any authenticated principal (read or admin)
- **U** the own account: any interactive browser session, viewers included (never API tokens)
- **A** admin (an admin's browser session or an admin token)
- **S** an admin's interactive browser session only (never API tokens): restore, update install, accounts, the HTTPS certificate, the listeners
- **X** (v0.15.0) the configuration export: an admin's browser session, an admin token or a sync token. A sync token reaches nothing else: every other route answers it 403 `forbidden` "this token can only read the configuration export" (`GET /auth/status` treats it as unauthenticated). Read tokens and viewers get 403 on X.

**Roles.** Accounts are admins or viewers (`auth.User.role`). A viewer's session has the scope `read`: every A and S route answers 403 "this action requires admin rights" (like a read token), R and U routes work. An admin token acts as `read` while its owner is a viewer. Roles are read on every request. U and S routes answer API tokens 403 "this action requires an interactive login".

**Web access.** Every request is attributed to its effective client (the TCP peer, or for a peer in `web.trustedProxies` the address its `X-Forwarded-For` names; ARCHITECTURE 2) and refused with 403 `forbidden` "this address may not use the web UI" when the web ACL does not allow it (with `Accept: text/html` a plain-text page names the address and `picache web-access --reset`); this applies to every path, `/healthz` and `/metrics` included. A trusted proxy's malformed `X-Forwarded-For` answers 400 `invalid` "malformed X-Forwarded-For header". Throttles, sessions, the audit log and the lookup defaults use the effective client.

**Configuration lock and destructive switch.** With `PICACHE_CONFIG_LOCKED` on, every *locked* route answers interactive sessions 403 `config_locked` "the configuration is locked on this host (PICACHE_CONFIG_LOCKED); change it with an admin API token or unset the variable" (tokens are not affected). Locked are all non-GET A and S routes except the exempt ones: `POST /system/restart`, `/system/update/check`, `/system/backups/scheduled/run`, `/dns/cache/flush`, `/dns/upstreams/test`, `/filter/lists/refresh`, `/filter/lists/{id}/refresh`, `/download-cache/source/refresh`, `/network/scan`, `/dhcp/probe`, `/notifications/channels/{id}/test`, `/storage/targets/{id}/test`, `/storage/targets/{id}/benchmark`, `/cache/verify`, `DELETE /storage/benchmark`, `PUT`/`DELETE /parental/groups/{id}/override` and `/pause`, `PUT`/`DELETE /system/log/level`, `POST /system/events/{id}/ack`, `POST /system/events/ack-all`, `POST /system/support-bundle`, `POST /dns/profile-links` (v0.14.0: a link changes no configuration), `POST /system/sync/run` (v0.15.0), `POST /dns/dnssec/test` (v0.17.0); `POST /dns/blocking` is locked only for a permanent disable (`enabled:false` without a positive `pauseSeconds`). With `PICACHE_DESTRUCTIVE_API=false` the *destructive* routes answer everyone 403 `forbidden` "this action is disabled on this host (PICACHE_DESTRUCTIVE_API=false)": `POST /system/restore`, `POST /dhcp/reset`, `DELETE /dhcp/leases`, `POST /cache/services/{service}/purge`, `POST /cache/groups/delete`, `POST /storage/targets/{id}/init`, `DELETE /storage/targets/{id}`, `DELETE /system/backups/scheduled/files/{name}`, `DELETE /system/users/{id}`, `DELETE /system/tls`, `DELETE /logs/queries`, `DELETE /stats`, `POST /clients/known/flush` (v0.15.0). Both checks come after authentication and the permission check, before the body is read, so the dry runs of `POST /filter/rules/import`, `/dns/records/import` and `/dns/forwarders/import` are locked like the imports. The batch routes (`POST …/batch`), `POST /filter/rules/device`, the IP-rule routes and `PUT /groups/{id}/upstreams` (v0.13.0) are locked and not destructive; so are `DELETE /clients/known` and `PUT /system/listeners` (v0.15.0). `GET /auth/status` reports both switches.

**Synced sections** (v0.15.0, ARCHITECTURE 15.4). While this PiCache is a follower (`sync.mode` `follower`), every route that writes a section it syncs answers every principal 409 `conflict` "this is synced from <origin>: change it on the primary": `clients-and-groups` = the `/clients` and `/groups` writes (batch and upstreams included) and `POST /filter/rules/device`; `lists-and-rules` = the writes and imports of `/filter/lists` (not the refreshes), `/filter/rules`, `/filter/ip-rules`, `POST /filter/rules/device` (it writes a rule as well) and a `PUT /parental/groups/{id}` that changes `categories` (field `categories`); `local-dns` = the writes and imports of `/dns/records` and `/dns/forwarders`; `parental` = `PUT /parental/groups/{id}` (overrides and pauses stay allowed); `dns-settings` = `PUT /settings` and `PATCH /settings/dns|filter` when they change a syncable member (field: that member, e.g. `dns.upstreams`) and `POST`/`DELETE /dns/blocked-clients`. The forget routes of seen data, restores and everything else stay allowed. `GET /auth/status` lists the synced sections.

**Password confirmation.** Creating an API token, starting TOTP enrolment, changing the password, disabling TOTP, restoring a backup, installing an update, managing accounts, uploading a certificate, creating a local CA, building a support bundle and (v0.15.0) saving the listeners ask for the current password again. Wrong passwords are throttled per client and per session (each: 5 failures → 15 min lockout) and by the global attempt limit (429 while blocked), but not by the username delay of sign-ins, and are audited as `auth.login_failed`. Confirmations in flight count as failures until they end, so concurrent ones get no more checks than the same ones in sequence (429 "too many attempts at once; try again in a few seconds").

All state-changing requests are protected by Go's `CrossOriginProtection` and audited.

**Errors.** `{"error":{"code":"invalid|not_found|conflict|forbidden|config_locked|unavailable|unauthorized|too_many_requests|internal|misdirected","message":"…","field":"dns.upstreams[1]"}}` with the matching HTTP status. An unexpected error is 500 `internal` "internal error (see server log)", except a write that failed because the data disk is full (SQLite `SQLITE_FULL`, `ENOSPC`): 503 `unavailable` "the data disk is full: free space on it (System → Health & about)" (sign-in and setup have their own message: `POST /auth/login`, `POST /auth/setup`). A read of the query log or the statistics that hits a damaged part of `logs.db` (SQLite `SQLITE_CORRUPT`, `SQLITE_NOTADB`) is 503 `unavailable` "logs.db is damaged: restart PiCache; it moves the file aside (System → Health & about)" (v1.0.0; before, 500).

**Lists.** Paged lists return `listing.Page[T]` = `{"items":[…],"total":N,"next":"cursor"}`. Offset lists take `limit`/`offset`; cursor lists take `limit`/`cursor`. Time ranges: `from`/`to` (RFC 3339 or unix seconds) or `range=15m|1h|6h|24h|7d|30d|90d|180d|365d` (any duration of at least a minute, or `Nd` up to 400 days; a range is at most 400 days).

**Streams.** SSE endpoints send `event: <name>` + `data: <json>`, a `: ping` comment every 15 s, re-validate the session every 15 s and end after 1 h (the browser reconnects) or when PiCache stops (at once, so a stream never delays a restart). At most 16 concurrent query and cache streams (429 beyond); the application log (`/stream/system-log`) has its own limit of 4 streams.

Ownership column = the `internal/api/routes_*.go` file that implements the endpoint.

**OpenAPI** (v0.16.0). [`internal/api/openapi.json`](../internal/api/openapi.json) describes every route of this document in OpenAPI 3.1 (JSON), maintained by hand next to it and served at `GET /api/v1/openapi.json` (below). Every operation carries `summary`, its parameters, request body and response schemas (errors as `components.responses.Error`), `x-picache-permission` (`P`|`R`|`U`|`A`|`S`|`X`), `x-picache-lock` (`none`|`locked`|`exempt`|`pause`), `x-picache-destructive` and `security` (P none; R, A and X the session cookie or a bearer token; U and S the session cookie only). `/healthz`, `/metrics` and `/dns-query` are listed with `x-picache-extra: true`. Its test (`internal/api/openapi_test.go`) checks that the set of operations equals the route registry (`{$}` removed, `{x...}` as `{x}`, a subtree pattern ending in `/` as `<pattern>{path}`), that permission, lock class and destructive flag equal the registry's, that every `$ref` resolves, and that `components.schemas.Settings` has exactly the JSON members of `settings.All`, recursively. The other response schemas are not checked against the code: this document stays the reference.

**Breaking changes in v0.2.0 (download cache names).** API clients written for v0.1.x have to switch to the new names; the old ones are not accepted as aliases.
- Settings: the download cache section of `settings.All` is `downloadCache` (`GET`/`PUT /settings`, `GET /settings/defaults`, `PATCH /settings/downloadCache`), and validation errors name the field `downloadCache.<member>` (e.g. `downloadCache.cacheIpv4[0]`).
- Routes: the download cache routes are under `/download-cache/…` with the same sub-paths as before (11 routes, see below).
- The DNS query status of answers with the cache address is `override` (query log, `status` filters, live stream); the DNS series key of `/stats/dns` is `override`, and the summary field is `logs.Summary.dnsDownloadCache`.
- JSON members: `/system/overview` `downloadCacheEnabled`; `clients.Client`/`clients.ClientInput` `downloadCacheBypass`.
- The health check is `download_cache`, and the audit actions of the download cache are `download_cache.*` (entries written before the upgrade keep their old action).
- Stored data is migrated automatically at the first start of v0.2.0, and a restored backup of v0.1.x at the start that applies it: the settings section (settings schema v2; an existing `downloadCache` section wins), the client bypass column (clients schema v2) and the query log and DNS rollups in logs.db (logs schema v2). Backups made by v0.2.0 are refused by v0.1.x (newer schema).

## Accounts — `routes_users.go`

Several accounts with the roles `admin` and `viewer` (at most 32; usernames 1–64 characters of `[A-Za-z0-9._@-]` starting with a letter or digit, unique case-insensitively, immutable). An admin's browser session only; every change asks for the caller's password (`currentPassword`, checked after the input and throttled like the other confirmations, audited as `auth.login_failed`). At least one admin always remains.

| Method & path | P | Request | Response |
|---|---|---|---|
| GET `/system/users` | S | – | `[]auth.User` (oldest first) |
| POST `/system/users` | S | `{username, password, role:"admin"|"viewer", currentPassword}` | 201 `auth.User`; 400 `field` `username`, `password` (≥ 10 characters), `role` ("must be admin or viewer") or `currentPassword`; 409 "an account named <name> already exists" or "at most 32 accounts can exist". Audited as `auth.user.create` (target: the username, details `{role}`) |
| PUT `/system/users/{id}` | S | `{role?, password?, disableTotp?:bool, currentPassword}` | 200 `auth.User`; 400 `body` "nothing to change" (no member, or only `disableTotp:false`), `role`, `password`, `currentPassword`; on the caller's own account only `role` may be given (400 with field `password` or `disableTotp` "change your own password and two-factor authentication under Your account"); 404; 409 "at least one admin must remain". A role change ends all sessions of the account, a demotion also deletes its admin and sync tokens (read tokens stay); a new `password` ends all its sessions and deletes all its API tokens (TOTP stays); `disableTotp:true` turns its TOTP off and ends its sessions (tokens stay). When the caller changed their own role, the response clears the session cookies (their sessions ended). Audited as `auth.user.update` (details `{role?, passwordReset, totpDisabled, sessionsRevoked, tokensRevoked}`) |
| DELETE `/system/users/{id}` | S | `{currentPassword}` (JSON body) | 204; 400 `currentPassword`; 404; 409 "at least one admin must remain". Sessions and API tokens of the account are deleted in the same transaction. Deleting oneself is allowed unless it removes the last admin; the response then clears the session cookies. Destructive. Audited as `auth.user.delete` (details `{role}`) |

## DHCP — `routes_dhcp.go`

- Reservation validation (400 with `field`): `mac` (colon- or hyphen-separated or 12 hex digits, stored lower case with colons; group and all-zero addresses refused; an existing reservation of the MAC on create), `ip` (a private IPv4 address; with a usable configured interface inside its subnet and not its network or broadcast address, PiCache's own or the router's address; not the address of another reservation), `hostname` (lower-cased; 1–63 of `a-z`, `0-9`, `-`, not starting or ending with `-`; not the name of another reservation; a name of the form `<a>-<b>-<c>-<d>` must be the generated name of its own address; `wpad` and `localhost` may be named explicitly), `comment` (at most 200 characters, no control characters), `clientId` (option 61 as colon-separated hex, 2–255 bytes, any case, stored lower-case; not the client identifier of another reservation), `leaseSeconds` (0 = `dhcp.leaseSeconds`, else 300–604800). More than 1024 reservations: 409. A reservation may lie outside the range; its client gets it at the next DISCOVER (a renewal of another address is answered with a NAK, so the client moves). The MAC is the key; a client whose MAC matches no reservation but whose option 61 equals a reservation's `clientId` gets that reservation while no active lease and no pending offer of another MAC holds the address and the neighbour check finds no other device on it (as forgeable as a MAC match: a convenience, not a security control). A reservation's `leaseSeconds` sets the lease time and T1/T2 on its address.
- Import (`POST /dhcp/static/import`): lines are split on LF (CRLF accepted) and numbered from 1 over the whole text, header and comment lines included. `csv`: RFC 4180 records of 4–6 fields `mac,ip,hostname,comment[,clientId[,leaseSeconds]]`; a first record whose first field is `mac` (any case) is the header; a leading `'` before `=`, `+`, `-`, `@`, TAB or CR is removed; empty lines are skipped. `hosts`: `ip name [aliases…] # mac [text]` — the name must be a host label, aliases and the text are ignored, the `# mac` comment is required (`field:"mac"` without it). `lines`: `mac ip [hostname]`. In `hosts` and `lines`, empty lines and lines starting with `#` are skipped. Every row is validated like `POST /dhcp/static`, plus MAC, address, host name and client identifier unique within the batch (the error is on the later line) and against the reservations that stay (with `replace` none). A known MAC is updated (the address always; `hostname`, `comment`, `clientId`, `leaseSeconds`: an absent column keeps the stored value, an empty field clears it; `lines` without a host name keeps it; `hosts` sets the host name and keeps the rest); a row equal to the stored reservation counts as `unchanged`; an unknown MAC is `added`; with `replace:true` every reservation whose MAC is not in the batch is `removed`. At most 1024 reservations in the end (`line:0, field:"text"`). `errors`: the first error of each line (`field` one of `mac`, `ip`, `hostname`, `comment`, `clientId`, `leaseSeconds`, `row` (field count, CSV quoting), `text`; batch errors have `line` 0), never `null`. With any error nothing is written (`applied:false`; the counts say what the valid rows would do); `dryRun` validates and counts only (`applied:false`). Otherwise one transaction (rows that are removed or updated are deleted first, then the added and updated ones inserted, so addresses can swap) and `applied:true`, `errors:[]`. Every call parses and validates anew.
- `dhcp.Status` = `{available:bool, reason?, reasonCode?, markerError?, deployment:"systemd"|"docker"|"other", state:"unavailable"|"off"|"blocked"|"serving"|"error", blockers:[string], error?, interface?:{name, mac, ipv4, prefixLen, dynamic:bool}, pool?:{start, end, size, used, static}, router?, dnsServer?, domain?, otherServers:[{address, serverId, source:"probe"|"request", lastSeen}], lastProbe?:{time, servers}, counters:{received, offers, acks, naks, declines, releases, informs, dropped}, ipv6:{routerAdvertisements:dhcp.RAStatus, dhcpv6:dhcp.DHCPv6Status, otherAnnouncers:[dhcp.Announcer], lastSearch?:{time, ra:bool, dhcpv6:bool}}}`. `available` is exactly `state != "unavailable"`: while DHCP is switched off on a supported installation the state is `off` and `available` true. `reasonCode` (with `state` `unavailable`): `opt-out` (`PICACHE_DHCP=off` is set), `not-linux`, `bridge` (a container bridge network), `socket` (UDP port 67 could not be opened: another DHCP server on this host, or no permission; retried every 30 s and on settings changes), `restart-required` (the ports open only at start in this installation, e.g. Docker: restart PiCache once; the marker is written so the next start opens them). `reason`: English text for the unavailable state, or (in another state) why the DHCP marker files could not be written. `markerError`: why the DHCP marker files could not be written, in every state (with `restart-required` a restart will not open the ports until it is fixed). `deployment`: `docker` (a Docker or Podman container), `systemd` (a systemd service), else `other`. `blockers` (while `blocked`, in this order): `dynamic-address` (PiCache's own IPv4 on the interface has a finite lifetime, i.e. comes from a DHCP client; cannot be overridden), `other-server` (another server answered a probe within 10 minutes, or a client's DHCPREQUEST named another server within 24 hours; also right after enabling until the first probe has run), `no-interface` (missing, down, virtual, no Ethernet address, or not exactly one private IPv4 address), `range` (the range does not fit the subnet or holds no address to hand out). `error`: e.g. no router address (no IPv4 default gateway in the subnet) or a failed probe. `interface`, `router`, `dnsServer` and `domain` are shown whenever the configured interface is usable; `pool.size` = addresses handed out dynamically (network, broadcast, PiCache's, the router's and the DNS server's addresses skipped), `pool.used` = active leases inside the range, `pool.static` = reservations. `otherServers`: the servers that count for the interface, newest first. `counters` count DHCPv4 packets since the start (`dropped`: malformed, rate limited, from a source outside the subnet or not for this server).
- `dhcp.RAStatus` = `{enabled:bool, available:bool, reason?, reasonCode?, state:"off"|"blocked"|"sending"|"error", blockers:[string], address?, lastSent?, sent, solicitations, error?}`: `available` is true while the raw ICMPv6 socket is open, and while the option is off and PiCache held `CAP_NET_RAW` at this start (switching it on then needs one restart). Otherwise `reasonCode`: `dhcp-unavailable` (DHCP itself is unavailable), `restart-required` (the option is on and PiCache held `CAP_NET_RAW` at this start; the raw socket opens at the next start), `no-cap-net-raw` (PiCache did not hold `CAP_NET_RAW` at this start; reported while the option is off too), `drop-unverified` (PiCache could not verify that `CAP_NET_RAW` was dropped and closed the socket), `socket` (opening it at start failed for another reason; `reason` says why). `blockers` `no-interface`, `no-ula` (no stable unique local IPv6 address on the interface), `no-raw-socket`; `address` = the announced ULA; `solicitations` = router solicitations answered. The IPv4 blockers (`dynamic-address`, `other-server`, `range`) do not stop the announcements; `state` is `off` while DHCP or the option is switched off.
- `dhcp.DHCPv6Status` = `{enabled:bool, state:"off"|"blocked"|"serving"|"error", blockers:[string], replies, ignored, error?}`: `blockers` `no-interface`, `no-ula`, `no-socket` (UDP port 547 could not be opened; `error` says why); `ignored` counts other message types (no address leases), malformed packets and relayed answers that are not for PiCache's search.
- `dhcp.Announcer` = `{kind:"ra"|"dhcpv6", address, interface, serverId?, dns:[addr], ownDns:[addr], managed?:bool, other?:bool, routerLifetime?:int, firstSeen, lastSeen, conflict:bool}` (newest first, never `null`, at most 32): another router whose advertisements announce DNS (RDNSS) or DHCPv6 (M/O flags; `managed`, `other`, `routerLifetime` in seconds only for `ra`; recorded only while PiCache's own router advertisements are on), or a DHCPv6 server that answered PiCache's relayed search (`serverId` as colon-separated hex only for `dhcpv6`; servers that do not answer relayed messages are seen only through the M/O flags). `ownDns`: the entries of `dns` that are addresses of this machine (PiCache itself; never `null`). `conflict`: while PiCache sends router advertisements or answers DHCPv6, the record carries a DNS server that is not an address of this machine and was seen at least twice; M/O flags alone never conflict. `lastSearch`: when the last search ran and whether its parts ran (`ra`: a router solicitation, only while the raw socket is open; `dhcpv6`: the relayed information request).
- `dhcp.Lease` = `{mac, ip, hostname?, clientId?, expires, active:bool, static:bool, clientName?, dnsName?, nameGenerated?:bool, nameConflict?:bool, vendor?:string, macRandomized?:bool}` (`vendor`, v0.15.0: the vendor of the MAC from the embedded IEEE registries; `macRandomized`: a locally administered MAC, which has no vendor; the UI shows "Private address (randomised)"): `hostname` = the reservation's name, else the one the client sent (sanitised to a DNS label; names of the form `<a>-<b>-<c>-<d>`, `wpad` and `localhost` from clients count as none); `clientId` = option 61 as colon-separated hex; `static`: the lease is on the address of its reservation (by MAC or client identifier); `clientName`: the configured client of the address or MAC; `dnsName` = `<hostname>.<domain>` while the lease is active and host names are registered, or the generated `<a>-<b>-<c>-<d>.<domain>` (`nameGenerated`, with `dhcp.generateNames`) when it has no usable name or `nameConflict` (another client holds the host name).
- `dhcp.StaticLease` = `{mac, ip, hostname?, comment?, clientId?, leaseSeconds?, createdAt, updatedAt, active:bool, vendor?:string, macRandomized?:bool}` (`leaseSeconds` left out when 0; `active`: the client holds an active lease on the address).
- `dhcp.LogEntry` = `{time, kind:"dhcpv4"|"dhcpv6"|"ra", mac?, duid?, address?, hostname?, in, out?, result, reason?}`: the last 200 handled exchanges (in memory, lost on restart). `in`: `DISCOVER`, `REQUEST`, `DECLINE`, `RELEASE`, `INFORM`, `INFORMATION-REQUEST`, `RS`; `out` (absent without an answer): `OFFER`, `ACK`, `NAK`, `REPLY`, `RA`; `result`: `answered`, `nak`, `processed`, `ignored`; `reason`: `rapid-commit`, `not-reserved`, `other-server`, `pool-exhausted`, `address-unavailable`, `move-to-reservation`, `client-id-conflict`. `mac` for DHCPv4 (and a router solicitation with a source link-layer address), `duid` = the DHCPv6 CLIENTID as colon-separated hex, `address` = the offered, acknowledged or requested address (DHCPv4) or the client's link-local source (DHCPv6, RS), `hostname` sanitised. Not recorded (only counted): malformed, rate-limited, foreign-interface or relayed packets, packets while not serving, periodic advertisements.
- Lease names (and generated names) are answered by the DNS server (step 7 of the pipeline, TTL min(300 s, remaining lease); local records win), and `POST /dns/lookup` shows the step `DHCP lease name: …`.

## DNS over HTTPS

RFC 8484 on `/dns-query` and `/dns-query/{dnsClientId}`, outside `/api/v1` (ARCHITECTURE 19): public (P), no lock class, not in the route registry; served on the HTTPS web listeners, on the dedicated listeners of `PICACHE_DOH_LISTEN` and on the plain web listener behind a trusted proxy that sends `X-Forwarded-Proto: https`. `/dns-query/` with an empty rest means no ClientID, one segment is the ClientID, more segments → 404.

| Request | Response |
|---|---|
| GET `?dns=<base64url>` (RFC 4648 §5; trailing `=` tolerated; other parameters ignored) or POST with `Content-Type: application/dns-message` (parameters ignored) and the message as body (≤ 64 KiB) | 200 `application/dns-message`: the reply with the query's ID (usually 0) and question case, `Cache-Control: private, max-age=<n>` (the smallest TTL of the reply's records outside OPT; 0 without records and for rcodes other than NOERROR and NXDOMAIN); never truncated. Rate limited → 200 with a REFUSED reply |

Errors (a short plain-text body, `Cache-Control: no-store`), in this order: 404 while `dns.encrypted.doh` is off (and, on the web listeners, for an effective scheme of http: the plain listener without a trusted proxy that sent `X-Forwarded-Proto: https`; never a redirect); 403 "DoH through a proxy that is not in web.trustedProxies is refused" (web listeners: a peer that is not trusted sends `X-Forwarded-For`, `Forwarded` or `X-Real-IP`) or "DoH through a proxy is served on the web listener only" (dedicated listeners: any of these headers); 405 with `Allow: GET, POST`; 403 "cross-site DoH requests are refused" (`Sec-Fetch-Site: cross-site` or `same-site`, or an `Origin` whose host differs from `Host`); 403 "this address may not use DNS" (the DNS ACL on the source: the effective client on the web listeners, the TCP peer on the dedicated ones; counted as refused; checked before the ClientID and the message are read); 400 "invalid ClientID"; 400 for a missing or undecodable `dns` parameter; 415 for another content type; 413 beyond 64 KiB; 400 for a message that does not unpack, has QR set or has no question; 429 with `Retry-After: 1` when 64 requests of the source's client key are in flight; 503 when 4096 client keys have requests in flight or the DNS server is overloaded. A query the pipeline drops (a blocked source, ClientID or identity, a dropped domain) resets only its stream (HTTP/2) or connection. On the web listeners the web ACL, the host allowlist (which accepts `dns.encrypted.serverName`) and `CrossOriginProtection` apply first; the dedicated listeners answer every other path with a bare 404 (no UI, API, `/healthz`, `/metrics`, cookies).

## Conventions for implementers

- Register routes with `s.route("GET /api/v1/…", permRead, handler, opts...)`; handlers return `error`. Permission constants: `permPublic` (P), `permRead` (R), `permSelf` (U), `permAdmin` (A), `permSession` (S). Every non-GET A or S route is locked by `PICACHE_CONFIG_LOCKED` unless registered with `routeExempt` (no stored configuration changes, nothing deleted) or `routePause`; add `routeDestructive` for routes that delete data in bulk or replace the configuration, and classify the route in `lock_routes_test.go`.
- Decode with `decode(w, r, &in)`; respond with `ok`, `created`, `noContent` or `writeJSON`.
- Handlers that may take long (list/source refresh, storage test, backup, restore) call `extendDeadlines(w, d)` first; SSE handlers use `sse(w, r, event, ch, alive)` with `alive = func() bool { return s.d.Auth.Valid(ctx, principal(r)) }`.
- Audit every successful state change with `s.audit(r, "<area>.<verb>", target, details)`; details are redacted by member name (password, token, secret, code, totp, setupToken, …). Never pass a token secret.
- Never return secrets (NAS password, notification secrets, token secrets except once at creation, TOTP secret except at begin).
- Validate path IDs with `pathID(r, "id")`; parse ranges with `qRange(r, 24*time.Hour)`.
