# PiCache REST API (v1)

Base path `/api/v1`. JSON only (`Content-Type: application/json` for request bodies; unknown members are rejected). Timestamps in entities are RFC 3339 (UTC); time series use unix seconds. Types in `code` refer to Go types (`package.Type`) whose JSON field names are authoritative.

**Auth.** Browser: session cookie set by login/setup (`HttpOnly`, `SameSite=Strict`, `Path=/`): `__Host-picache_session` (always `Secure`) when the request's effective scheme is https (it arrived over TLS, or a peer in `web.trustedProxies` sent `X-Forwarded-Proto: https`), `picache_session` otherwise (`Secure` only with `PICACHE_WEB_SECURE_COOKIES=true`, for a TLS-terminating reverse proxy that is not trusted). Both names are accepted. Login and setup also set a device cookie, named the same way (`__Host-picache_device` over https, `picache_device` otherwise; `HttpOnly`, `SameSite=Strict`, 180 days, sealed with the master key, renewed at every sign-in, kept on logout). It is not a credential: a later sign-in with the same username from that browser is throttled by the device (5 failures → 15 min) instead of the username delay. Automation: `Authorization: Bearer <token>` (API tokens, scope `read` or `admin`). Permissions:
- **P** public
- **R** any authenticated principal (read or admin)
- **U** the own account: any interactive browser session, viewers included (never API tokens)
- **A** admin (an admin's browser session or an admin token)
- **S** an admin's interactive browser session only (never API tokens): restore, update install, accounts, the HTTPS certificate

**Roles.** Accounts are admins or viewers (`auth.User.role`). A viewer's session has the scope `read`: every A and S route answers 403 "this action requires admin rights" (like a read token), R and U routes work. An admin token acts as `read` while its owner is a viewer. Roles are read on every request. U and S routes answer API tokens 403 "this action requires an interactive login".

**Web access.** Every request is attributed to its effective client (the TCP peer, or for a peer in `web.trustedProxies` the address its `X-Forwarded-For` names; ARCHITECTURE 2) and refused with 403 `forbidden` "this address may not use the web UI" when the web ACL does not allow it (with `Accept: text/html` a plain-text page names the address and `picache web-access --reset`); this applies to every path, `/healthz` and `/metrics` included. A trusted proxy's malformed `X-Forwarded-For` answers 400 `invalid` "malformed X-Forwarded-For header". Throttles, sessions, the audit log and the lookup defaults use the effective client.

**Configuration lock and destructive switch.** With `PICACHE_CONFIG_LOCKED` on, every *locked* route answers interactive sessions 403 `config_locked` "the configuration is locked on this host (PICACHE_CONFIG_LOCKED); change it with an admin API token or unset the variable" (tokens are not affected). Locked are all non-GET A and S routes except the exempt ones: `POST /system/restart`, `/system/update/check`, `/system/backups/scheduled/run`, `/dns/cache/flush`, `/dns/upstreams/test`, `/filter/lists/refresh`, `/filter/lists/{id}/refresh`, `/download-cache/source/refresh`, `/network/scan`, `/dhcp/probe`, `/notifications/channels/{id}/test`, `/storage/targets/{id}/test`, `/storage/targets/{id}/benchmark`, `/cache/verify`, `DELETE /storage/benchmark`, `PUT`/`DELETE /parental/groups/{id}/override` and `/pause`, `PUT`/`DELETE /system/log/level`, `POST /system/events/{id}/ack`, `POST /system/events/ack-all`, `POST /system/support-bundle`; `POST /dns/blocking` is locked only for a permanent disable (`enabled:false` without a positive `pauseSeconds`). With `PICACHE_DESTRUCTIVE_API=false` the *destructive* routes answer everyone 403 `forbidden` "this action is disabled on this host (PICACHE_DESTRUCTIVE_API=false)": `POST /system/restore`, `POST /dhcp/reset`, `DELETE /dhcp/leases`, `POST /cache/services/{service}/purge`, `POST /cache/groups/delete`, `POST /storage/targets/{id}/init`, `DELETE /storage/targets/{id}`, `DELETE /system/backups/scheduled/files/{name}`, `DELETE /system/users/{id}`, `DELETE /system/tls`, `DELETE /logs/queries`, `DELETE /stats`. Both checks come after authentication and the permission check, before the body is read, so the dry runs of `POST /filter/rules/import`, `/dns/records/import` and `/dns/forwarders/import` are locked like the imports. The batch routes (`POST …/batch`), `POST /filter/rules/device`, the IP-rule routes and `PUT /groups/{id}/upstreams` (v0.13.0) are locked and not destructive. `GET /auth/status` reports both switches.

**Password confirmation.** Creating an API token, starting TOTP enrolment, changing the password, disabling TOTP, restoring a backup, installing an update, managing accounts, uploading a certificate, creating a local CA and building a support bundle ask for the current password again. Wrong passwords are throttled per client and per session (each: 5 failures → 15 min lockout) and by the global attempt limit (429 while blocked), but not by the username delay of sign-ins, and are audited as `auth.login_failed`.

All state-changing requests are protected by Go's `CrossOriginProtection` and audited.

**Errors.** `{"error":{"code":"invalid|not_found|conflict|forbidden|config_locked|unavailable|unauthorized|too_many_requests|internal|misdirected","message":"…","field":"dns.upstreams[1]"}}` with the matching HTTP status.

**Lists.** Paged lists return `listing.Page[T]` = `{"items":[…],"total":N,"next":"cursor"}`. Offset lists take `limit`/`offset`; cursor lists take `limit`/`cursor`. Time ranges: `from`/`to` (RFC 3339 or unix seconds) or `range=15m|1h|6h|24h|7d|30d|90d|180d|365d` (any duration of at least a minute, or `Nd` up to 400 days; a range is at most 400 days).

**Streams.** SSE endpoints send `event: <name>` + `data: <json>`, a `: ping` comment every 15 s, re-validate the session every 15 s and end after 1 h (the browser reconnects). At most 16 concurrent query and cache streams (429 beyond); the application log (`/stream/system-log`) has its own limit of 4 streams.

Ownership column = the `internal/api/routes_*.go` file that implements the endpoint.

**Breaking changes in v0.2.0 (download cache names).** API clients written for v0.1.x have to switch to the new names; the old ones are not accepted as aliases.
- Settings: the download cache section of `settings.All` is `downloadCache` (`GET`/`PUT /settings`, `GET /settings/defaults`, `PATCH /settings/downloadCache`), and validation errors name the field `downloadCache.<member>` (e.g. `downloadCache.cacheIpv4[0]`).
- Routes: the download cache routes are under `/download-cache/…` with the same sub-paths as before (11 routes, see below).
- The DNS query status of answers with the cache address is `override` (query log, `status` filters, live stream); the DNS series key of `/stats/dns` is `override`, and the summary field is `logs.Summary.dnsDownloadCache`.
- JSON members: `/system/overview` `downloadCacheEnabled`; `clients.Client`/`clients.ClientInput` `downloadCacheBypass`.
- The health check is `download_cache`, and the audit actions of the download cache are `download_cache.*` (entries written before the upgrade keep their old action).
- Stored data is migrated automatically at the first start of v0.2.0, and a restored backup of v0.1.x at the start that applies it: the settings section (settings schema v2; an existing `downloadCache` section wins), the client bypass column (clients schema v2) and the query log and DNS rollups in logs.db (logs schema v2). Backups made by v0.2.0 are refused by v0.1.x (newer schema).

## Accounts — `routes_users.go`

Several accounts with the roles `admin` and `viewer` (at most 32; usernames 1–64 characters of `[A-Za-z0-9._@-]` starting with a letter or digit, unique case-insensitively, immutable). An admin's browser session only; every change asks for the caller's password (`currentPassword`, checked after the input and throttled like the other confirmations, audited as `auth.login_failed`). At least one admin always remains.

| Method & path | P | Request | Response |
|---|---|---|---|
| GET `/system/users` | S | – | `[]auth.User` (oldest first) |
| POST `/system/users` | S | `{username, password, role:"admin"|"viewer", currentPassword}` | 201 `auth.User`; 400 `field` `username`, `password` (≥ 10 characters), `role` ("must be admin or viewer") or `currentPassword`; 409 "an account named <name> already exists" or "at most 32 accounts can exist". Audited as `auth.user.create` (target: the username, details `{role}`) |
| PUT `/system/users/{id}` | S | `{role?, password?, disableTotp?:bool, currentPassword}` | 200 `auth.User`; 400 `body` "nothing to change" (no member, or only `disableTotp:false`), `role`, `password`, `currentPassword`; on the caller's own account only `role` may be given (400 with field `password` or `disableTotp` "change your own password and two-factor authentication under Your account"); 404; 409 "at least one admin must remain". A role change ends all sessions of the account, a demotion also deletes its admin tokens (read tokens stay); a new `password` ends all its sessions and deletes all its API tokens (TOTP stays); `disableTotp:true` turns its TOTP off and ends its sessions (tokens stay). When the caller changed their own role, the response clears the session cookies (their sessions ended). Audited as `auth.user.update` (details `{role?, passwordReset, totpDisabled, sessionsRevoked, tokensRevoked}`) |
| DELETE `/system/users/{id}` | S | `{currentPassword}` (JSON body) | 204; 400 `currentPassword`; 404; 409 "at least one admin must remain". Sessions and API tokens of the account are deleted in the same transaction. Deleting oneself is allowed unless it removes the last admin; the response then clears the session cookies. Destructive. Audited as `auth.user.delete` (details `{role}`) |

Section `dns` — members added in v0.9.0 (defaults in brackets; lists are never `null`; a stored document without them loads with these defaults, ARCHITECTURE 13):
- `fallbackUpstreams:[string]` (`["https://security.cloudflare-dns.com/dns-query"]`; `[]` = off): asked only when no default upstream replied at all (transport errors, timeouts; never after a reply of any rcode), same syntax as `upstreams`, at most 4 (`dns.fallbackUpstreams` "at most 4 entries", `dns.fallbackUpstreams[i]`).
- `upstreamBlockedTtl:int` (`300`): cache lifetime in seconds of answers the default upstreams blocked themselves, 10–86400 (`dns.upstreamBlockedTtl`).
- `rebindProtection:bool` (`true`) and `rebindAllow:[string]` (`["plex.direct"]`): DNS rebinding protection for answers of the default set; `rebindAllow` are domains (with their subdomains) that may resolve to private addresses, host names lower-cased without the trailing dot, duplicates removed, at most 256 (`dns.rebindAllow`, `dns.rebindAllow[i]` "must be a domain name").
- `domainNeeded:bool` (`true`): single-label names (A, AAAA, HTTPS, SVCB, ANY) are answered as `<name>.<localDomain>` and never sent to the default upstreams (ARCHITECTURE 7.1 step 11a).
- `privateReverseNetworks:[string]` (`[]`): networks whose reverse zones are served locally like the RFC 6303 zones; at most 32 (`dns.privateReverseNetworks`); IPv4 /8, /16 or /24, IPv6 /16–/124 in steps of 4, host bits masked, duplicates removed, zones refused (`dns.privateReverseNetworks[i]` "must be an IPv4 /8, /16 or /24 or an IPv6 prefix whose length is a multiple of 4 between /16 and /124").
- `blockedClients:[string]` (`[]`): IP addresses, CIDRs (at least /8 IPv4, /32 IPv6) or MAC addresses whose DNS queries get no answer at all (DNS only); normalised (addresses unmapped, CIDRs masked, a full-length CIDR becomes the address, MACs lower-case with colons, `-` accepted), duplicates removed, at most 256 (`dns.blockedClients`, `dns.blockedClients[i]`). See also `POST /dns/blocked-clients`.
- `rateLimitIpv4Prefix:int` (`32`, 8–32) and `rateLimitIpv6Prefix:int` (`64`, 32–64): the networks public sources share one rate-limit bucket by; LAN sources (loopback, RFC 1918, CGNAT, link-local, ULA, on-link) are always limited per address (`dns.rateLimitIpv4Prefix`, `dns.rateLimitIpv6Prefix`).
- `droppedDomains:[string]` (`[]`): `domain` or `domain:TYPE` (the domain and its subdomains; a mnemonic type or `TYPEnnn`, 1–65535) whose queries get no answer at all and are not logged; the domain needs two labels and may not be `arpa` or below it or below `localhost`, `test`, `invalid`, `onion`, `local` or `internal`; normalised (domain lower-case, TYPE upper-case, `TYPEnnn` of a known type as its mnemonic), duplicates removed, at most 256 (`dns.droppedDomains`, `dns.droppedDomains[i]`).
- `bogusNxdomain:[string]` (`[]`): addresses or CIDRs (at least /8 IPv4, /32 IPv6, host bits masked) that turn an answer of the default set into NXDOMAIN (status `special`, reason `bogus-nxdomain`); at most 64 (`dns.bogusNxdomain`, `dns.bogusNxdomain[i]`).
- `bootstrapPreferIpv6:bool` (`false`): the resolved addresses of DoT, DoH and named plain upstreams are dialled IPv6 first.
- `ecs:{mode:"off"|"client"|"custom", customSubnet:string}` (`{"off",""}`): the EDNS client subnet sent to the default upstreams; `client` = the /24 or /56 of a public source address, `custom` = `customSubnet`, a public IPv4 /8–/24 or IPv6 /32–/56 network (required for `custom`, checked whenever set: not private, CGNAT, link-local, documentation or another special-use range; host bits masked) (`dns.ecs.mode` "must be off, client or custom", `dns.ecs.customSubnet`).
- `ednsClientTrusted:[string]` (`[]`): forwarders whose queries may name the client by EDNS (one ECS option with a full-length address, one option 65001 with a MAC); single addresses (a /32 or /128 CIDR is stored as the address; unspecified, multicast and zones refused; loopback allowed), at most 16 (`dns.ednsClientTrusted`, `dns.ednsClientTrusted[i]` "must be a single IP address"). - Import (`POST /dns/forwarders/import`): `text` has one forwarder per line (LF, CRLF accepted; numbered from 1; empty lines and lines starting with `#` are skipped): `[/d1/d2/…/]t1 t2 …` — the domains between slashes (an empty one, as in `[//]`, is `(unqualified)`), then 1–8 whitespace-separated targets; the target `#` means `default`. A line without a leading `[/…/]` is an error with `field:"syntax"`; each line is validated like `POST /dns/forwarders` (`field` `domains` or `upstreams`); a domain repeated in the import is an error on the later line. A line whose first domain is an existing forwarder's `domain` updates it (domains and targets replaced; `enabled` and `comment` kept; identical → `unchanged`); another domain of a line that belongs to a different existing forwarder is an error (`domains`, naming it); other lines are `added` (enabled, empty comment). More than 256 forwarders in the end → `{line:0, field:"text"}`. `errors` holds the first error of each line (at most 256, sorted by line, never `null`). Any error → nothing is written (`applied:false`; the counts say what the valid lines would do); `dryRun` only validates and counts; otherwise everything is written in one transaction (`applied:true`).

The IPv4 blockers (`dynamic-address`, `other-server`, `range`) do not stop the announcements; `state` is `off` while DHCP or the option is switched off.
- `dhcp.DHCPv6Status` = `{enabled:bool, state:"off"|"blocked"|"serving"|"error", blockers:[string], replies, ignored, error?}`: `blockers` `no-interface`, `no-ula`, `no-socket` (UDP port 547 could not be opened; `error` says why); `ignored` counts other message types (no address leases), malformed packets and relayed answers that are not for PiCache's search.
- `dhcp.Announcer` = `{kind:"ra"|"dhcpv6", address, interface, serverId?, dns:[addr], ownDns:[addr], managed?:bool, other?:bool, routerLifetime?:int, firstSeen, lastSeen, conflict:bool}` (newest first, never `null`, at most 32): another router whose advertisements announce DNS (RDNSS) or DHCPv6 (M/O flags; `managed`, `other`, `routerLifetime` in seconds only for `ra`; recorded only while PiCache's own router advertisements are on), or a DHCPv6 server that answered PiCache's relayed search (`serverId` as colon-separated hex only for `dhcpv6`; servers that do not answer relayed messages are seen only through the M/O flags). `ownDns`: the entries of `dns` that are addresses of this machine (PiCache itself; never `null`). `conflict`: while PiCache sends router advertisements or answers DHCPv6, the record carries a DNS server that is not an address of this machine and was seen at least twice; M/O flags alone never conflict. `lastSearch`: when the last search ran and whether its parts ran (`ra`: a router solicitation, only while the raw socket is open; `dhcpv6`: the relayed information request).
- `dhcp.Lease` = `{mac, ip, hostname?, clientId?, expires, active:bool, static:bool, clientName?, dnsName?, nameGenerated?:bool, nameConflict?:bool}`: `hostname` = the reservation's name, else the one the client sent (sanitised to a DNS label; names of the form `<a>-<b>-<c>-<d>`, `wpad` and `localhost` from clients count as none); `clientId` = option 61 as colon-separated hex; `static`: the lease is on the address of its reservation (by MAC or client identifier); `clientName`: the configured client of the address or MAC; `dnsName` = `<hostname>.<domain>` while the lease is active and host names are registered, or the generated `<a>-<b>-<c>-<d>.<domain>` (`nameGenerated`, with `dhcp.generateNames`) when it has no usable name or `nameConflict` (another client holds the host name).
- `dhcp.StaticLease` = `{mac, ip, hostname?, comment?, clientId?, leaseSeconds?, createdAt, updatedAt, active:bool}` (`leaseSeconds` left out when 0; `active`: the client holds an active lease on the address).
- `dhcp.LogEntry` = `{time, kind:"dhcpv4"|"dhcpv6"|"ra", mac?, duid?, address?, hostname?, in, out?, result, reason?}`: the last 200 handled exchanges (in memory, lost on restart). `in`: `DISCOVER`, `REQUEST`, `DECLINE`, `RELEASE`, `INFORM`, `INFORMATION-REQUEST`, `RS`; `out` (absent without an answer): `OFFER`, `ACK`, `NAK`, `REPLY`, `RA`; `result`: `answered`, `nak`, `processed`, `ignored`; `reason`: `rapid-commit`, `not-reserved`, `other-server`, `pool-exhausted`, `address-unavailable`, `move-to-reservation`, `client-id-conflict`. `mac` for DHCPv4 (and a router solicitation with a source link-layer address), `duid` = the DHCPv6 CLIENTID as colon-separated hex, `address` = the offered, acknowledged or requested address (DHCPv4) or the client's link-local source (DHCPv6, RS), `hostname` sanitised. Not recorded (only counted): malformed, rate-limited, foreign-interface or relayed packets, packets while not serving, periodic advertisements.
- Lease names (and generated names) are answered by the DNS server (step 7 of the pipeline, TTL min(300 s, remaining lease); local records win), and `POST /dns/lookup` shows the step `DHCP lease name: …`.

The client: the configured client that identifies the address when none of its identifiers is a CIDR, otherwise a new one (named after the device's host name as `GET /clients/known` reports it, else the address; identifiers the address and its neighbour-table MAC unless that MAC is the router's, this machine's or a trusted forwarder's or belongs to another client; the groups and flags of the CIDR client covering it, else Default). The client keeps all its groups and gains this one. The rule: one with the same action, type and pattern and identical options gains the group (`createdRule:false`); other options → 409; otherwise a new rule for the device group only. When the rule step fails, the clients change is undone.
- Search (`GET /filter/search`): `q` trimmed and lower-cased, 3–253 bytes of printable ASCII (400 `q`); `limit` 1–200, default 200 (400 `limit`); `clientIp` optional (400 `clientIp`). Matches: rules and IP rules whose pattern contains `q` (id order; `entry` = the export line), then list entries of the enabled lists with a local copy (id order, never downloaded) whose domain or source line contains `q` (`entry` = the line as the parser reads it: trimmed, without its inline ` #` comment, invalid UTF-8 removed, at most 1100 bytes cut at a character boundary; entries cancelled by a `$badfilter` of the same list are not shown, also after 1000 hits); `name` = the rule pattern or list name. Stops at `limit` hits (`truncated`) or after 10 s (`timedOut`, the hits so far with 200). `totalLists` = the lists to read, `scannedLists` = those read completely. It shares Explain's two slots and does not wait for one (503). `enabled`: the flag of a rule or IP rule (`true` for list entries: only enabled lists are searched). `applies` only with `clientIp`: the entry shares an enabled group with the client (pauses ignored); rules and IP rules that are disabled have `applies:false`. `category` is a catalogue category or `other` (own lists); `allow` exactly for kind `allow`; anything else → 400 `field:"category"`. `catalogKey` is the key of the catalogue entry with exactly this URL (`""` for own lists). An enabled list of the categories `adult`, `gambling`, `dating`, `piracy` or `doh-vpn-bypass` is a **protection list**: enforced like parental controls (also while blocking is paused or disabled; the allow override and allowlists do not lift it, a user allow rule does). A category change into or out of `abused-tlds` re-parses the list: every other list counts a subtree, wildcard or pattern block of a single label or an ICANN public suffix (`||com^`, `*.co.uk`, `||*.com^`, `.com^`, `/\.xyz$/`) as invalid. `tldBlocksIgnored` (int, never stored) is the number of such entries in the loaded copy (part of `invalid`; 0 while no copy is loaded, e.g. for a disabled list).

## Conventions for implementers

- Register routes with `s.route("GET /api/v1/…", permRead, handler, opts...)`; handlers return `error`. Permission constants: `permPublic` (P), `permRead` (R), `permSelf` (U), `permAdmin` (A), `permSession` (S). Every non-GET A or S route is locked by `PICACHE_CONFIG_LOCKED` unless registered with `routeExempt` (no stored configuration changes, nothing deleted) or `routePause`; add `routeDestructive` for routes that delete data in bulk or replace the configuration, and classify the route in `lock_routes_test.go`.
- Decode with `decode(w, r, &in)`; respond with `ok`, `created`, `noContent` or `writeJSON`.
- Handlers that may take long (list/source refresh, storage test, backup, restore) call `extendDeadlines(w, d)` first; SSE handlers use `sse(w, r, event, ch, alive)` with `alive = func() bool { return s.d.Auth.Valid(ctx, principal(r)) }`.
- Audit every successful state change with `s.audit(r, "<area>.<verb>", target, details)`; details are redacted by member name (password, token, secret, code, totp, setupToken, …). Never pass a token secret.
- Never return secrets (NAS password, notification secrets, token secrets except once at creation, TOTP secret except at begin).
- Validate path IDs with `pathID(r, "id")`; parse ranges with `qRange(r, 24*time.Hour)`.
